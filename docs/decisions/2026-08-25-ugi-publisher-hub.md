# ADR — UGI Publisher Hub replaces chat-dependent render and publication

Date: 2026-08-25  
Status: accepted

## Decision

UGI render reconciliation and publication are orchestrated by **UGI Publisher Hub**, independent of any ChatGPT conversation or Lola 5.3 runtime.

The canonical state lives in the repository:

- queue: `control-plane/publisher-hub/queue/`
- render state: `control-plane/publisher-hub/render-state/`
- receipts: `control-plane/publisher-hub/receipts/`
- status: `control-plane/publisher-hub/status/latest.json`
- workflow: `.github/workflows/ugi-publisher-hub.yml`
- render reconciler: `scripts/ugi_render_reconciler.py`
- publication runtime: `scripts/ugi_publisher_hub.py`

Buffer remains the sole scheduler/publisher. The deployed UGI Worker remains the authoritative render/publication API boundary. Metricool remains read-only analytics.

## Root cause closed by this decision

The legacy `ugi-chat-control-plane.yml` workflow dispatched `render-video.yml` directly. That bypassed Worker `/api/video-render`, so the video result could reach R2 without the `approvalDraftId` correlation used by `/api/video-upload` and the approval draft. Media could therefore be ready while publication remained blocked waiting for a linked draft.

Production video generation must now enter through Worker `/api/video-render`. The legacy render control plane is forward-only and may not dispatch `render-video.yml` directly.

## Runtime contract

`manifest -> Publisher Hub -> Worker /api/video-render -> approvalDraftId/draft -> GitHub renderer -> R2 platform assets -> Worker health -> Buffer channels -> platform approval -> eligibility -> Buffer schedule -> live readback -> receipt`

A render is never considered linked without the Worker/draft correlation. A schedule is never declared proven without a `bufferPostId` and matching `dueAt` returned by readback.

## Autonomy

The hub runs on:
1. canonical queue changes;
2. explicit workflow dispatch;
3. a 15-minute reconciliation schedule.

No chat session has to be open. Once queue + content commands exist, the Hub owns render reconciliation, draft readiness, scheduling and evidence.

## Compatibility

`control-plane/chat-publication/*.json` is legacy publication input only. `.github/workflows/ugi-chat-publication.yml` only forwards to Publisher Hub.

`.github/workflows/ugi-chat-control-plane.yml` is legacy render input only. It only wakes Publisher Hub and performs no direct renderer dispatch.

Existing orphaned media generated by the former direct-dispatch path is not used as publication proof. The Hub generates/reconciles a correctly tracked render through the Worker contract instead of publishing an unlinked asset.

## Exactly-once and retry

Existing Worker/Buffer publication state is read before any create. A manifest with a proven receipt is skipped. Per-content render state prevents blind duplicate render dispatch while a Worker render is in flight. A waiting/degraded manifest remains safely retryable. The existing Buffer exactly-once/idempotency contract remains authoritative.

## Fail-closed

Publication is blocked/degraded when:
- Worker health cannot be proven;
- queued content has no command source;
- render correlation cannot be proven;
- Buffer channels cannot be read;
- routing policy stops naming Buffer as exclusive provider;
- Metricool becomes write-enabled;
- project isolation is not UGI;
- platform eligibility fails;
- final Buffer readback cannot prove the post and schedule.

## Rollback

Disable `.github/workflows/ugi-publisher-hub.yml` and restore the previous workflows from Git history. No Buffer migration or credential change is required. Restoring direct GitHub renderer dispatch is not a valid production rollback unless draft correlation is also restored and proven.
